## Setup do `aluno_id` — por que existe e como fazer

Nesta aula a turma inteira vai gravar dados **no mesmo servidor**. Se todo mundo gravasse junto, sua lista de tarefas ia se misturar com a dos 30 colegas. Para separar, **cada aluno escolhe um identificador único** (o `aluno_id`) e o servidor só te devolve as tarefas que têm o **seu** id.

Você vai usar esse id em **toda** chamada ao servidor. Em vez de digitar toda hora, a gente grava ele **uma vez** numa "memória" do navegador chamada **`localStorage`**.

> 🧠 **O que é `localStorage`?** Uma caixinha de chave→valor que o navegador guarda **mesmo depois de fechar a aba ou desligar o PC**. `localStorage.setItem('aluno_id', 'ana_42')` guarda; `localStorage.getItem('aluno_id')` lê de volta. É separado por site.

Crie `lab23/setup.html`, abra no navegador, digite um id único (nome + número, ex: `ana_souza_42`) e clique salvar:

```html
<!DOCTYPE html>
<html lang="pt-br"><head><meta charset="utf-8"><title>Setup</title>
<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script></head>
<body>
  <h1>Configuração do aluno</h1>
  <input id="id" placeholder="ex: ana_souza_42">
  <button id="salvar">Salvar</button>
  <p id="msg"></p>
  <script>
    $('#salvar').on('click', function () {
      var id = $('#id').val().trim();
      if (id === '') { $('#msg').text('Digite algo!'); return; }
      localStorage.setItem('aluno_id', id);   // grava no navegador
      $('#msg').text('Salvo! Seu aluno_id é: ' + id);
    });
  </script>
</body></html>
```

Feito isso, **todo** arquivo da aula vai começar lendo esse id:

```js
var ALUNO_ID = localStorage.getItem('aluno_id');   // lê o que você salvou no setup
```

> 📌 **O servidor da aula** guarda só uma coisa: **tarefas**. Cada tarefa é um objeto assim:
> ```
> { id: 7, aluno_id: "ana_42", titulo: "Estudar jQuery", feito: 0, criado_em: "2026-06-19 20:11" }
> ```

## A.1 — Relembrando o jQuery

Tudo em jQuery começa com **`$()`**: você passa um **seletor** (igual ao do CSS) e ela te devolve o elemento pra você mexer. Quatro ferramentas que você já viu:

**a) Mudar o conteúdo — `.text()`**
`$('#titulo')` encontra o elemento de `id="titulo"`. O `.text('...')` troca o texto dentro dele.
```js
$('#titulo').text('Olá, turma!');   // o #titulo passa a mostrar "Olá, turma!"
```

**b) Reagir a um clique — `.on('click', função)`**
"Quando clicarem nesse elemento, rode esta função."
```js
$('#botao').on('click', function () {
  $('#saida').text('Você clicou!');
});
```

**c) Reagir enquanto digita — `.on('input', função)`**
O evento `input` dispara a **cada tecla** num campo. O `.val()` lê o que está escrito.
```js
$('#campo').on('input', function () {
  $('#eco').text( $('#campo').val() );   // espelha ao vivo o que você digita
});
```

**d) Sortear um item de uma lista**
`Math.random()` dá um número entre 0 e 1; multiplicando pelo tamanho do array e arredondando pra baixo com `Math.floor`, vira um **índice válido**.
```js
var emojis = ['🔥', '💯', '🚀', '😎'];
var sorteado = emojis[ Math.floor(Math.random() * emojis.length) ];
```

**e) Ligar/desligar uma classe CSS — `.toggleClass('nome')`**
Se o elemento não tem a classe, adiciona; se já tem, remove. Ótimo pra "ligar/desligar" um estilo.
```js
$('body').toggleClass('escuro');   // 1º clique liga o tema escuro, 2º desliga
```

## A.2 — Ler do servidor: `$.getJSON`

Até agora seus dados ficavam escritos no próprio arquivo HTML. O problema: pra mudar a lista, você tinha que **editar o código**. A web real não é assim — os dados ficam num **servidor** (outro computador, na internet) e o navegador **pede** quando precisa. Pedir dados ao servidor **sem recarregar a página** se chama **AJAX**.

> 🍽️ **Analogia do garçom.** Você (o navegador) faz um pedido. O garçom (o AJAX) leva até a cozinha (o servidor) e volta com o prato (os dados). Enquanto ele vai e volta, **você continua na mesa, conversando** — não fica congelado. Quando o prato chega, aí sim você come. Esse "continuar a vida enquanto o pedido não volta" é o que chamamos de **assíncrono**.

No jQuery, o comando pra **buscar** dados (em JSON) é o **`$.getJSON`**:

```js
$.getJSON(API + '?aluno_id=' + ALUNO_ID, function (tarefas) {
  // este bloco SÓ roda quando a resposta chega (pode levar 1 segundinho)
  // 'tarefas' é um array com as suas tarefas
});
```

⚠️ **O detalhe que confunde todo mundo:** aquela `function (tarefas) {...}` **não roda na hora**. Ela fica guardada e só é chamada **quando o servidor responder**. Por isso **todo** código que usa os dados precisa ficar **dentro** dela (chamamos de *callback*). Se usar `tarefas` fora, ainda não chegou nada.

**Exemplo resolvido — montar uma lista `<ul id="lista">`:**
```js
function listar() {
  $.getJSON(API + '?aluno_id=' + ALUNO_ID, function (tarefas) {
    $('#lista').empty();                      // 1. limpa antes de redesenhar
    $.each(tarefas, function (i, t) {         // 2. percorre o array; 't' é uma tarefa
      $('<li>').text(t.titulo).appendTo('#lista');   // 3. cria um <li> e põe na <ul>
    });
  });
}
listar();   // chama assim que a página abre
```

Ferramentas novas aí:
- **`.empty()`** — esvazia o elemento (senão duplicaria tudo a cada listagem).
- **`$.each(array, função)`** — roda a função **uma vez para cada item**. O `t` é o item da vez.
- **`$('<li>')`** — com `<li>` dentro, isso **cria** um elemento novo; `.appendTo('#lista')` coloca ele na `<ul>`.

> 💡 `tarefas.length` te dá a **quantidade** de itens. Na primeira vez a lista vem vazia (você ainda não criou nada — criar é a próxima parte).

## A.3 — Criar no servidor: `$.post`

Ler é metade. Agora vamos **gravar**. Se `$.getJSON` é "me dê os dados", o **`$.post`** é "guarde este dado pra mim".

> 🍽️ Voltando ao garçom: antes você **pedia** um prato (GET). Agora você está **mandando** um pedido novo pra cozinha registrar (POST). Ela registra e confirma: "anotado, pedido nº 7".

A API precisa de dois campos pra criar: **`aluno_id`** (de quem é) e **`titulo`** (o quê). O terceiro argumento é o callback, que roda quando o servidor confirma:

```js
$.post(API, { aluno_id: ALUNO_ID, titulo: 'Estudar jQuery' }, function (criada) {
  console.log('Gravei a tarefa de id', criada.id);  // 'criada' é a tarefa já com id
});
```

### O padrão de ouro: formulário → criar → recarregar

Quase sempre o usuário cria digitando num formulário e apertando Enter. Mas tem uma armadilha: por padrão, quando um `<form>` é enviado, **o navegador recarrega a página inteira** — e aí seu AJAX nem chega a rodar. Pra impedir isso usamos **`e.preventDefault()`** ("previna o comportamento padrão"). É o herói da aula. 🦸

**Exemplo resolvido:**
```js
$('#form').on('submit', function (e) {
  e.preventDefault();                        // 1. impede o reload da página
  var titulo = $('#titulo').val().trim();    // 2. lê o campo (.trim() tira espaços das pontas)
  if (titulo === '') return;                 // 3. campo vazio? não faz nada
  $.post(API, { aluno_id: ALUNO_ID, titulo: titulo }, function () {
    $('#titulo').val('').focus();            // 4. limpa o campo e devolve o cursor
    listar();                                // 5. recarrega a lista
  });
});
```

Métodos de campo: **`.val()`** lê; **`.val('')`** apaga; **`.focus()`** põe o cursor de volta (pra digitar a próxima sem o mouse).

> 🚫 **Evitar clique-duplo:** `.prop('disabled', true)` desliga o botão; `.prop('disabled', false)` religa quando termina.

## A.4 — Quando dá erro (e validação)

Servidor real **falha**: a internet cai, o dado vai errado. Um app profissional **não trava** — ele avisa com jeito. Em vez de passar a função de sucesso direto no `$.post`, dá pra encadear `.done()`, `.fail()` e `.always()`:

```js
$.post(API, { aluno_id: ALUNO_ID, titulo: titulo })
  .done(function (criada) { listar(); })                          // ✅ deu certo
  .fail(function (xhr)   { alert('Deu ruim 😕 (' + xhr.status + ')'); })  // ❌ deu erro
  .always(function ()    { $('#enviar').prop('disabled', false); });      // 🔁 SEMPRE roda
```

- **`.done`** roda se respondeu OK.
- **`.fail`** roda se falhou. `xhr.status` traz o código: `400` = dado inválido, `500` = erro no servidor, `0` = sem internet.
- **`.always`** roda **nos dois casos** — perfeito pra religar o botão aconteça o que acontecer.

### Validação visual (sem `alert` chato)
A classe `.erro` deixa o campo com borda vermelha. Tire ela assim que o usuário digitar de novo:
```js
if ($('#titulo').val().trim() === '') {
  $('#titulo').addClass('erro').focus();   // fica vermelho e ganha o cursor
  return;                                  // e NÃO envia
}
$('#titulo').removeClass('erro');
```
```js
$('#titulo').on('input', function () { $('#titulo').removeClass('erro'); });
```

### Feedback que aparece e some — `.fadeIn` / `.fadeOut` + `setTimeout`
`.fadeIn()` faz surgir suave; `.fadeOut()` faz sumir suave. `setTimeout(função, 2000)` roda a função depois de 2000 ms (2s).
```js
$('#aviso').fadeIn();                                      // aparece
setTimeout(function () { $('#aviso').fadeOut(); }, 2000);  // some depois de 2s
```
