## Setup obrigatório — seu `aluno_id` (faça UMA vez)

### Por que isso existe

Nesta aula a turma inteira vai gravar dados **no mesmo servidor**. Se todo mundo gravasse no mesmo monte, sua lista de tarefas ia se misturar com a dos 30 colegas — uma bagunça. Para separar, **cada aluno escolhe um identificador único** (o `aluno_id`) e o servidor só te devolve as tarefas que têm o **seu** id.

Você vai usar esse id em **toda** chamada ao servidor. Em vez de digitar toda hora, a gente grava ele **uma vez** numa "memória" do navegador chamada **`localStorage`**.

> 🧠 **O que é `localStorage`?** É uma caixinha de chave→valor que o navegador guarda **mesmo depois de fechar a aba ou desligar o PC**. `localStorage.setItem('aluno_id', 'ana_42')` guarda; `localStorage.getItem('aluno_id')` lê de volta. É separado por site, então só as suas páginas enxergam.

### Faça agora

Crie `lab23/setup.html`, abra no navegador, digite um id único (nome + número, ex: `ana_souza_42`) e clique salvar:

```html
<!DOCTYPE html>
<html lang="pt-br"><head><meta charset="utf-8"><title>Setup</title>
<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script></head>
<body>
  <h1>Configuração do aluno</h1>
  <input id="id" placeholder="ex: ana_souza_42">
  <button id="salvar">Salvar</button>
  <p id="msg"></p>
  <script>
    $('#salvar').on('click', function () {
      var id = $('#id').val().trim();
      if (id === '') { $('#msg').text('Digite algo!'); return; }
      localStorage.setItem('aluno_id', id);   // grava no navegador
      $('#msg').text('Salvo! Seu aluno_id é: ' + id);
    });
  </script>
</body></html>
```

Feito isso, **todo** arquivo da aula vai começar lendo esse id:

```js
var ALUNO_ID = localStorage.getItem('aluno_id');   // lê o que você salvou no setup
```

> 📌 **O servidor da aula.** Ele guarda só uma coisa: **tarefas**. Cada tarefa é um objeto assim:
> ```
> { id: 7, aluno_id: "ana_42", titulo: "Estudar jQuery", feito: 0, criado_em: "2026-06-19 20:11" }
> ```
> Como `titulo` é texto livre, dá pra usar pra qualquer coisa: recados, desculpas, memes, playlist... 😏

# Parte 1 — Relembrando o jQuery

## Explicação

Antes de falar com o servidor, vamos reaquecer as 4 ferramentas de jQuery que você já viu nas aulas 1 e 2. Tudo em jQuery começa com a função **`$()`**: você passa um **seletor** (igual ao do CSS) e ela te devolve o elemento pra você mexer.

**a) Mudar o conteúdo de um elemento — `.text()`**
`$('#titulo')` encontra o elemento de `id="titulo"`. O `.text('...')` troca o texto dentro dele.
```js
$('#titulo').text('Olá, turma!');   // o #titulo passa a mostrar "Olá, turma!"
```

**b) Reagir a um clique — `.on('click', função)`**
Você diz: "quando clicarem nesse elemento, rode esta função". A função é o que acontece no clique.
```js
$('#botao').on('click', function () {
  $('#saida').text('Você clicou!');
});
```

**c) Reagir enquanto a pessoa digita — `.on('input', função)`**
O evento `input` dispara a **cada tecla** num campo. O `.val()` lê o que está escrito no campo naquele momento.
```js
$('#campo').on('input', function () {
  $('#eco').text( $('#campo').val() );   // espelha ao vivo o que você digita
});
```

**d) Sortear um item de uma lista**
`Math.random()` dá um número quebrado entre 0 e 1 (ex: 0.37). Multiplicando pelo tamanho do array e arredondando pra baixo com `Math.floor`, viramos um **índice válido** (0, 1, 2...).
```js
var emojis = ['🔥', '💯', '🚀', '😎'];
var sorteado = emojis[ Math.floor(Math.random() * emojis.length) ];
```

**e) Ligar/desligar uma classe CSS — `.toggleClass('nome')`**
Se o elemento **não** tem a classe, ela é adicionada; se **já** tem, é removida. Ótimo pra "ligar/desligar" um estilo.
```js
$('body').toggleClass('escuro');   // 1º clique liga o tema escuro, 2º desliga
```

# Parte 2 — Ler do servidor: `$.getJSON`

## Explicação

Até agora seus dados ficavam escritos no próprio arquivo HTML. O problema: pra mudar a lista, você tinha que **editar o código**. A web real não é assim — os dados ficam num **servidor** (outro computador, na internet) e o navegador **pede** quando precisa.

Essa técnica de pedir dados ao servidor **sem recarregar a página** se chama **AJAX**.

> 🍽️ **Analogia do garçom.** Você (o navegador) faz um pedido. O garçom (o AJAX) leva até a cozinha (o servidor) e volta com o prato (os dados). Enquanto ele vai e volta, **você continua na mesa, conversando** — não fica congelado olhando pra cozinha. Quando o prato chega, aí sim você come. Esse "continuar a vida enquanto o pedido não volta" é o que chamamos de **assíncrono**.

No jQuery, o comando pra **buscar** dados (em formato JSON) é o **`$.getJSON`**:

```js
$.getJSON(API + '?aluno_id=' + ALUNO_ID, function (tarefas) {
  // este bloco SÓ roda quando a resposta chega (pode levar 1 segundinho)
  // 'tarefas' é um array com as suas tarefas
});
```

⚠️ **O detalhe que confunde todo mundo:** aquela `function (tarefas) {...}` dentro do `$.getJSON` **não roda na hora**. Ela fica guardada e só é chamada **quando o servidor responder**. Por isso **todo** código que usa os dados precisa ficar **dentro** dela (chamamos essa função de *callback*, "me ligue de volta quando chegar"). Se você tentar usar `tarefas` fora, ainda não chegou nada.

## Exemplo resolvido (comentado)

Montar uma lista `<ul id="lista">` com o título de cada tarefa:

```js
function listar() {
  $.getJSON(API + '?aluno_id=' + ALUNO_ID, function (tarefas) {
    $('#lista').empty();                      // 1. limpa a lista antes de redesenhar
    $.each(tarefas, function (i, t) {         // 2. percorre o array; 't' é uma tarefa
      $('<li>').text(t.titulo).appendTo('#lista');   // 3. cria um <li> e põe na <ul>
    });
  });
}
listar();   // chama a função pra carregar assim que a página abre
```

Três ferramentas novas apareceram aí:
- **`.empty()`** — esvazia o elemento (senão, cada vez que listar, duplicaria tudo).
- **`$.each(array, função)`** — roda a função **uma vez para cada item** do array. O `t` é o item da vez.
- **`$('<li>')`** — repare: com `<li>` dentro, isso **cria** um elemento novo. O `.appendTo('#lista')` coloca ele dentro da `<ul>`.

> 💡 `tarefas.length` te dá a **quantidade** de itens — útil pra contar. E na **primeira vez** a lista vem vazia, porque você ainda não criou nada (criar é a Parte 3).

# Parte 3 — Criar no servidor: `$.post`

## Explicação

Ler é metade da história. Agora vamos **gravar**. Se `$.getJSON` é "me dê os dados", o **`$.post`** é "guarde este dado pra mim".

> 🍽️ Voltando ao garçom: antes você **pedia** um prato (GET). Agora você está **mandando** um pedido novo pra cozinha registrar (POST). A cozinha registra e te confirma: "anotado, pedido nº 7".

A nossa API precisa de dois campos pra criar uma tarefa: o **`aluno_id`** (de quem é) e o **`titulo`** (o quê). O terceiro argumento é o callback, que roda quando o servidor confirma:

```js
$.post(API, { aluno_id: ALUNO_ID, titulo: 'Estudar jQuery' }, function (criada) {
  // 'criada' é a tarefa que o servidor gravou, já com id
  console.log('Gravei a tarefa de id', criada.id);
});
```

### O padrão de ouro: formulário → criar → recarregar

Quase sempre o usuário cria a tarefa **digitando num formulário** e apertando Enter. Mas tem uma armadilha: por padrão, quando um `<form>` é enviado, **o navegador recarrega a página inteira** — e aí seu AJAX nem chega a rodar.

Pra impedir esse recarregamento usamos **`e.preventDefault()`** (literalmente: "previna o comportamento padrão"). É o herói da aula. 🦸

## Exemplo resolvido (comentado)

```js
$('#form').on('submit', function (e) {
  e.preventDefault();                        // 1. impede o reload da página
  var titulo = $('#titulo').val().trim();    // 2. lê o campo (.trim() tira espaços das pontas)
  if (titulo === '') return;                 // 3. campo vazio? não faz nada
  $.post(API, { aluno_id: ALUNO_ID, titulo: titulo }, function () {
    $('#titulo').val('').focus();            // 4. limpa o campo e devolve o cursor
    listar();                                // 5. recarrega a lista pra mostrar a nova
  });
});
```

Métodos de campo que aparecem aí: **`.val()`** lê o texto; **`.val('')`** apaga o texto; **`.focus()`** põe o cursor de volta no campo (pra digitar a próxima sem usar o mouse).

> 🚫 **Bônus — evitar clique-duplo:** se a internet estiver lenta, o usuário pode clicar duas vezes e criar duplicado. `.prop('disabled', true)` **desliga** o botão; `.prop('disabled', false)` **religa** quando termina.

# Parte 4 — Quando dá erro (e validação)

## Explicação

Servidor real **falha**: a internet cai, o dado vai errado, o servidor tem um problema. Um app profissional **não trava** quando isso acontece — ele avisa o usuário com jeito.

Até agora a gente passou a função de sucesso direto no `$.post(...)`. Existe um jeito melhor, que separa **o que fazer se der certo** de **o que fazer se der errado**, encadeando `.done()`, `.fail()` e `.always()`:

```js
$.post(API, { aluno_id: ALUNO_ID, titulo: titulo })
  .done(function (criada) { listar(); })                          // ✅ deu certo
  .fail(function (xhr)   { alert('Deu ruim 😕 (' + xhr.status + ')'); })  // ❌ deu erro
  .always(function ()    { $('#enviar').prop('disabled', false); });      // 🔁 SEMPRE roda
```

- **`.done`** roda se o servidor respondeu OK.
- **`.fail`** roda se algo falhou. O `xhr.status` traz o **código do erro**: `400` = você mandou um dado inválido, `500` = problema no servidor, `0` = sem internet.
- **`.always`** roda **nos dois casos** — perfeito pra "religar o botão" aconteça o que acontecer.

### Validação visual — avisar sem `alert` chato

`alert` trava a tela. Mais elegante é deixar o **campo com borda vermelha** (a classe `.erro`) quando o usuário tenta enviar vazio, e tirar o vermelho assim que ele volta a digitar:

```js
if ($('#titulo').val().trim() === '') {
  $('#titulo').addClass('erro').focus();   // fica vermelho e ganha o cursor
  return;                                  // e NÃO envia
}
$('#titulo').removeClass('erro');          // passou na validação: tira o vermelho
```
```js
$('#titulo').on('input', function () { $('#titulo').removeClass('erro'); });
```

### Feedback que aparece e some — `.fadeIn` / `.fadeOut` + `setTimeout`

`.fadeIn()` faz o elemento **surgir suave**; `.fadeOut()` faz **sumir suave**. O `setTimeout(função, 2000)` roda a função depois de 2000 milissegundos (2s). Juntando, dá pra mostrar um aviso que some sozinho:

```js
$('#aviso').fadeIn();                                      // aparece
setTimeout(function () { $('#aviso').fadeOut(); }, 2000);  // some depois de 2s
```
